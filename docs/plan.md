# Gramene Knowledge Graph — implementation plan (increment 1: SorghumBase v11)

## Context

Gramene and SorghumBase host many kinds of data objects (germplasm accessions, assembled genomes, gene models, variants, genotypes, populations, phenotypes/QTLs, expression experiments, pathways, ontology terms, gene trees, publications, user gene lists) but they live in separate stores: per-release Mongo dbs (`sorghum11`, `search70`), Solr cores, the shared `ontology`/`ensembl` dbs, the g2p BrAPI server, Redis, FASTA/VCF/TSV files and Ensembl REST. Links between them are implicit — embedded ids on 5.4M gene documents, ids packed into Solr field *names* (`E_MTAB_5956_g3__expr`, `VEP__stop_gained__het__sorghum_bicolor__9__attr_ss`), and a hand-written field crosswalk (`KB_RELATIONS`) in `gramene-mcp`. Nothing records where a link came from, from which source version, by what method, or on whose authority; QTL ids, Compara metrics, ontology versions, Reactome evidence and experiment citations are all dropped by today's ETL. Nothing lets a curator record a paper, an analysis or a collection that ties objects together.

The goal is a knowledge graph in which every data object, collection, analysis, annotation and publication is a node, every link is a typed, attributed edge, an n-ary relation can itself be a node, and provenance is first-class — searchable, browsable, and usable by AI agents through the existing MCP server.

Exploration (2026-10-27, read-only) produced digests of six areas, three independent designs, six critiques, one synthesis and three reviews of this plan; they are in `/tmp/claude-553/-usr-local-gramene/ee0ffef5-9af4-4835-b1f6-d85568cd96fc/scratchpad/` (`explore-*.md`, `design-*.md`, `critiques.md`, `synthesis.md`, `plan-review.md`). M0 copies `synthesis.md` and `plan-review.md` into the new repo as `docs/design.md` and `docs/design-review.md` (the review corrects several statements in the synthesis; where they disagree, this plan and the review win).

## Decisions taken with the user

1. **First scope: SorghumBase v11** (`sorghum11`: 128 genomes, 9 anchors, germplasm, rsIDs, VEP LoF, EBI+JGI expression, g2p for phenotypes). Loaders are species-agnostic; `search70` is the second load.
2. **Writers: ETL per release plus curators** (Firebase auth, g2p-style ACLs) for publications, analyses, collections and links.
3. **Model: property graph with a standards vocabulary** — LinkML profile of Biolink 4.4.6, RO predicates where Biolink maps them, PROV-O activities, Bioregistry CURIEs, ECO evidence. JSON-LD/RDF are exports only: increment 1 ships KGX TSV + KGX JSON lines + a JSON-LD context (together valid JSON-LD); graph-wide N-Quads/Turtle dumps are M5.
4. **Store: phased** — DuckDB/Parquet → validated KGX → new Mongo db + Solr core first; Neo4j Community 5.26 LTS only after sizes are measured (M5).
5. **Deployment: new repo `warelab/gramene-kg`**, own pm2 apps on port 12000 (12001 dev), proxied at `/kg` on data.sorghumbase.org; `gramene-mcp` gains `kg_*` tools.

### Defaults adopted (object at approval if you disagree)
- **g2p deviation from decision 1**: g2p is not a node source in increment 1. Its only published version (`test@9`) belongs to a *private* dataset and holds genotypes (SAP, 397 samples, 2,421 SNPs on the anchor assembly), not phenotypes; g2p has no phenotype files at all (manifest kinds are only `germplasm` and `vcf`). A `kg10` source stub reads `gramene_g2p.datasetVersions{status:published}` joined to `datasets{visibility:public}` and emits Dataset/Distribution nodes plus sample→Dataset membership under `infores:gramene-g2p`, so public phenotype/genotype datasets flow in later without code changes.
- **Not answerable in increment 1** (stated in SKILL.md and the schema slices too): phenotype observations on germplasm (traits exist only as TO terms via QTL→TO and rice-only rap-db gene→TO on 3,855 genes); per-variant genotype calls for a sample (`GenotypedSample` carries only VEP LoF consequence×zygosity calls for 32,277 genes, populations 1–8); genotype×phenotype associations; expression *values* and homolog *pairs* except through `/derived`.
- Gene CURIE is `gramene.gene:<stable_id>` for all 5.4M genes; `ensembl:` only as an xref on anchor ids that match the Bioregistry pattern (≈89% of sorghum11 ids, e.g. `353.001G000500`, `Sobic.001G000100`, do not).
- Germplasm is two levels: `GermplasmAccession` (per stock centre) + `GenotypedSample` (`ens_id`). Populations come from a curated TSV with a species column; pops 6/12/15 are rice (3,341 accessions) and load as `oryza_sativa` populations with `species_confidence: inferred`.
- Population 9 (Sorghum Genomics Toolbox, 940 `SGT_*` sample ids, 27.7M LoF values, **no germplasm docs**) is excluded from LoF edges; the Population node carries the counts.
- `not_expressed` organ calls become `negated: true` edges (hidden by default); `no_data` is dropped.
- Rice Gramene_QTLdb containment edges (≈2.38M) are included (rice is an anchor).
- Publication nodes for all 9 anchors (≈22.2k after parsing), enriched once from NCBI esummary + Crossref and cached forever.
- Public gene lists/saved views become Collection nodes (27 today; recounted each build); owner display names only with `display_opt_in`.
- Requests filed at M0: gorgonzola `ProxyPass /kg → squam:12000` + firewall; Bioregistry pattern updates for `gramene.gene`/`gramene.qtl` and new `gramene.*` prefixes; infores registrations (see Provenance); ask the host owner to persist `cacheSizeGB: 64` in `/etc/mongod.conf`.

## Design

### Schema — `schema/gramene_kg.yaml` (LinkML plant profile of Biolink)
`imports: [linkml:types, vendor/biolink-model-4.4.6]` — the Biolink YAML is **vendored** at `schema/vendor/biolink-model-4.4.6.yaml` (from `raw.githubusercontent.com/biolink/biolink-model/v4.4.6/…`, sha256 in `manifest.json`), because `biolink:biolink-model` resolves through w3id to the floating latest. `default_prefix: gramene`. Generates `schema/generated/{json-schema,typescript,jsonld/context.jsonld,docs,schema-slices.json}`. Python venv `.venv` (python3.12) holds `linkml`, `duckdb`, `kgx`.

**Prefixes** (`config/prefixes.yaml` drives the id gate, not Bioregistry): `insdc.gca`, `NCBITaxon`, `GO`, `PO`, `TO`, `ECO`, `SO`, `interpro`, `reactome`, `dbsnp` (resolver override to pansite-ensembl-115), `PMID`, `doi`, `gxa.expt`, `bioproject`, `infores`; local `gramene.{gene,genome,taxon,genetree,qtl,germplasm,sample,population,varstudy,expt,assay,contrast,tffamily,collection,term,analysis,run,release,dataset,dist,software,agent,assoc}` resolving to `https://data.sorghumbase.org/kg/ui/node/<encoded curie>`. Local ids never contain `/`; **any CURIE placed in a URL path segment is percent-encoded** (`encodeURIComponent`) because DOIs contain `/` (65 of 66 IDF DOIs, e.g. `doi:10.1101/gr.227462.117`); the API decodes params (find-my-way decodes `%2F` after matching), and UI links, the resolver template and `kg://` resources use the encoded form.

Mongo and the API keep the `gramene:` predicates; **the KGX projection writes the nearest Biolink predicate** (`has_part`, `related_to`) in `predicate` and the `gramene:` CURIE in `original_predicate`, and writes only non-mixin Biolink classes in `category` with the gramene class in a `gramene:class` column — KGX's validator errors on anything else.

**Provenance slots on every edge** (KGX columns): `id` (sha256-24 of `subject|predicate|object|primary_knowledge_source|identity qualifiers`; for `layer == curated` the `assertion_id` is included so two workspaces asserting the same triple never collide), `primary_knowledge_source` (infores from `config/infores.yaml`, which carries `registered: true|false` and `registry_pr` — only `infores:go`, `infores:interpro`, `infores:ensembl-gene`, `infores:dbsnp`, `infores:ncbi-gene`, `infores:reactome` exist in the registry today; `infores:ensembl-gene` is used for Ensembl gene-model edges; the others are provisional until the M0 PRs land, kg30 warns, the API exposes `registered`), `aggregator_knowledge_source[]`, `knowledge_level` and `agent_type` (exact enum names; kg30 checks membership), `has_evidence[]` (ECO; declared `slot_usage: range: evidence type` as a documented deviation, plus `gramene:evidence_code_label`), `original_evidence` (`IEA`, `IDK`, `none`, `''`), `publications[]`, `has_supporting_studies[]` (bioproject on variant edges, gxa.expt on expression edges), `release`, `ingest_run`, `method`, `original_subject`/`original_object`, `source_record`, `knowledge_source_version` (the *edge source's* version, e.g. GO `releases/2026-06-15` from the release tree — not the node set's `ontology.loads` 2026-07-26; both are Dataset nodes), `negated`, `score`, `layer` (etl|curated), `assertion_id/rev`.

**Evidence-map defaults** (`config/evidence-map.yaml`, keyed by source *and* genome where needed): GO IEA → `automated_agent`, `prediction`, ECO:0000501; every other GO code → `manual_agent`, `knowledge_assertion`, ECO via `GOECO:<code>` xref. Curated PO/TO: rice rap-db → manual, knowledge_assertion, ECO:0000352, `infores:rap-db`, original `IDK`; arabidopsis PO (TAIR via Ensembl core xrefs, evidence `''`) → `infores:tair` (provisional), `agent_type not_provided`, no ECO, original `''`. Trees/orthologs = prediction, computational_model, ECO:0000080. InterPro = prediction, automated_agent, ECO:0000259. Reactome = prediction, computational_model (orthology projections; evidence `none` for all non-rice rows; the 2,519 rice `TAS` rows map to knowledge_assertion/manual/ECO:0000304). QTL containment = logical_entailment, data_analysis_pipeline, method `qtl-containment@<git7>`; QTL→trait = statistical_association, manual_agent, ECO:0000061. Mentions = manual (GeneRIF/rap-db/CSHL are curated). Organ expression = observation, data_analysis_pipeline, ECO:0006069, method `gramene.analysis:expression_attributes@<sha>`. Variant→gene = logical_entailment, method `rsid-windowing@<params sha>` (`RSID_*` in `config.sh:78-117`). LoF = prediction, computational_model, `infores:ensembl-variation`, method `vep-lof-table@v10`.

**Reification rule**: plain edge when metadata is 1:1 with one source (all ETL edges in increment 1 except ExpressionContrast); promote to `Association` when curators add a second evidence line, when a relation needs its own citation/retraction history, or arity exceeds subject/object + qualifiers.

**Identity resolution** (`build/sql/identity.sql`, shared by `/resolve` and curated attach): Gene exact `_id` → `alt_id` → `synonyms`, **all matches returned with genome** — `Sobic.007G158500` is the `_id` of a `sorghum_bicolort2tcas` gene *and* the alt_id of `SORBI_3007G158500`, so a bare alias hit is `ambiguous` unless `genome=` is given (default anchor `GCA_000003195.3`). `normaliseId` (g2p `validate.ts:328-330`) only for germplasm/sample/population strings. Trees never equated across compara dbs except via `leafset_sha1`.

## Risks and mitigations
- **RAM** (MemAvailable ≈100 GB, swap 52/64 GB used, WiredTiger 55 of 64 GB): stream everything, DuckDB `memory_limit 16GB` with temp on /scratch, kg00 admission gates, off-peak loads, lean edge docs, two edge indexes only.
- **HDD cold latency** (7.2k RAID-6; KG pages evict live release pages): measure warm and cold at M1a; honest SLOs (p95 < 1 s cold, < 300 ms warm); small working set.
- **Edge counts were underestimated in early drafts** (QTL 3.5M, variants 4.5M, LoF 3.1M): `expectations.json` recorded from measured builds, ±10% gates, per-QTL cap.
- **Public exposure depends on others** (gorgonzola, CSHL firewall): requested at M0; everything usable on localhost/VPN meanwhile.
- **Curated layer is the only non-reproducible asset on an unauthenticated mongod**: nightly dumps, `content_sha256` per revision, kg00 refuses to target `kg_meta`/`kg_curation`, write client hard-coded.
- **Identity churn across releases** (tree ids, synthetic taxa, non-GCA genomes): never foreign keys outside a release; `leafset_sha1`, `genome_registry.tsv`, curator warnings, attach reports each build.
- **Upstream fetch failures** (NCBI, Crossref, EBI FTP, dev.gramene.org feeds): sha256-stamped snapshots, cache-first, `unenriched` flags; a curated-feed outage fails loudly (unlike `curated.js:17`).
- **DuckDB Node binding on EL8**: fallback to the venv Python module, decided at M0.
- **Solr atomic-update erasure**: all kept fields stored; preflight check at kg70. **/solr is the tightest mount** (183 GB free): cores 1–2 GB, two builds retained.
- **Mixed ontology versions** (nodes from `ontology.*` 2026-07/110.0, edges from release tree 2026-06/109.0): separate Dataset nodes + `knowledge_source_version`; alt_id resolution keeps dangling at zero.
- **Standards drift**: Biolink vendored and pinned; KGX export is a Biolink-flattened projection while the native `gramene:` predicates stay in Mongo/API; infores ids marked registered/provisional.
- **Never**: `pm2 restart all`; restart or re-checkout live apps ad hoc; touch `search*`/`sorghum*`/`userData1`/Solr release cores; query colden; copy credentials from `ensembl_db_info.json`.
