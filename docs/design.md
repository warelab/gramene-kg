# gramene-kg — merged executable design (increment 1 = SorghumBase v11)

All counts, paths and line numbers below were re-verified read-only on 2026-10-27 (mongosh on `sorghum11`/`ontology`/`userData1`/`gramene_g2p`, Solr `:8983`, files under `/usr/local/gramene/subsites/sorghum/v11`, `/scratch/olson/rsid_projection`, Bioregistry and the `pansite-ensembl-115` REST mirror). Everything honours the five brief decisions: sorghum11 first with species-agnostic loaders and `search70` second; ETL + Firebase/g2p-ACL curators; Biolink/RO/PROV-O/Bioregistry model with JSON-LD/RDF as exports only; phased store (DuckDB/Parquet → KGX → new Mongo db + Solr core, Neo4j CE 5.26 later); new `warelab/gramene-kg` repo, pm2, `/kg` on data.sorghumbase.org, `gramene-mcp` gains tools.

## Decisions between the three designs (one sentence each)

1. **Gene CURIE = `gramene.gene:<stable_id>`** (ops-minimal), not `ensembl:` — the Bioregistry `ensembl` pattern rejects 5,153,097 of 5,407,132 sorghum11 ids (`353.001G000500`, `Sobic.001G000100`, `SbRio.01G000100.v2.1` all fail; verified with node), and `ensembl:` is emitted only as an xref on the 9 anchor genomes whose ids match.
2. **Germplasm is two levels** (consumer-first): `GermplasmAccession` keyed per stock centre and `GenotypedSample` keyed by `ens_id` — 389 accessions span more than one `ens_id` and only ARS dbids are GRIN ids.
3. **Populations come from a curated TSV with a species column** (critics of all three) — pops 6, 12, 15 are 3,341 rice accessions (`IRIS_313-*`, `USDA_GSOR*`, `WRC*/JRC*`) and the germplasm docs carry no species field.
4. **Taxonomy folds on `rank == 'genome'` then resolves against `ontology.ncbi_taxonomy`** — the `<1e6` rule misclassifies Ecdysozoa (1206794, real) and "Sorghum pan" (455800000, synthetic) and 65 real taxa in search70.
5. **Per-build Mongo db + pointer flip** (standards critic) instead of rebuilding into the served `kg_<release>` db — Mongo 5.0 cannot swap several collections atomically, so immutability and ETags only hold if a build lands in its own db and promotion is one document update.
6. **Small Solr core** (ops-minimal): non-Gene/non-Variant nodes plus the 288,734 anchor-genome genes with cards (≈540k docs), not 5.6M docs with 8 KB cards — gene text search already exists in `sorghum_suggestions11`/`sorghum_genes11` and the `/search` route merges it.
7. **Publications for all 9 anchors (≈22.2k nodes)** (standards) — the anchor rule and the "≤300 lookups" cap cannot both stand (22,168 distinct ids measured); 111 esummary batches of 200 plus 168 Crossref calls is ~5 minutes once, cached forever.
8. **LoF as 3,120,315 Sample→Gene pair edges** (new) rather than a reified `LofCallSet` with `carriers[]` or 31.8M/52.6M edges — once `VEP__merged__*` (20.8M values) and population 9 (27.7M values, no germplasm docs) are excluded, 4,081,054 values collapse to 3.12M pairs, which fits the plain-edge rule.
9. **`expressed_in` only for low/medium/high/very_high; `not_expressed` as `negated=true` edges hidden by default; `no_data` dropped** (all critics) — 941,697 of the "level ≠ no_data" cells are negative calls.
10. **Curated assertions flow through the build as a source (kg20) *and* the API masks baked edges whose assertion is no longer published** (both critics' fixes combined) — fresh builds get curated degree/cards, retractions still take effect immediately.
11. **Reactome nodes are species-prefixed stable ids (`reactome:R-SBI-…`) with `base_id`; edges default to `prediction`/`computational_model`** — seven species prefixes exist in gene entries (R-SBI, R-ZMY, R-ATH, R-PTI, R-VVN, R-SMO, R-CRE) and the evidence column is `none` for all 291,505 rows.
12. **Variants keep `dbsnp:rs…` syntax with a documented Ensembl-REST resolver override** — `eva.variant` has no Bioregistry pattern, and rs ids are what agents and `sorghum_suggestions11` already use.
13. **Derived homology Parquet is built every release** (standards) — `search/tmp_homologs/{homology,homology_member}.tsv.gz` (verified headers `homology_id, description, gene_tree_root_id` and `homology_id, gene_member_id, perc_pos`) is the only place the dropped Compara metrics survive.
14. **MCP tools are staged on a new `gramene-mcp-kg` pm2 process and folded into `gramene-mcp` at its next scheduled restart** (standards) — the live process is never restarted ad hoc.
15. **UI = React + Vite static bundle served by the Fastify app at `/kg/ui`** (standards/consumer) — the toolchain is already proven on this host by gramene-g2p and one `/kg` ProxyPass covers API, UI and downloads.
16. **Port 12000** (two of three designs; verified free along with 12001–12019 and 7474/7687); 12001 is reserved for a dev instance.
17. **Local ids never contain `/`** — Fastify `:curie` matches one path segment, so `gramene.qtl:QPGYR5.1` (ids are unique across both QTL sources), `gramene.population:sorghum_bicolor.5`, `gramene.assay:E-MTAB-5956.g1`.

## 1. Increment-1 scope

### What a sorghum researcher or agent gets that does not exist today
1. Gene → QTL **by id** (today `addQtlXrefs.js:58-67` keeps only the TO union): 5,843 Sorghum_QTL_Atlas + 7,123 Gramene_QTLdb QTLs as nodes, containment recomputed (≈1.15M sorghum + ≈2.48M rice edges; sample of 200 protein-coding genes per map: 32.4 and 63.5 QTLs/gene).
2. Variant (rsID) → gene → QTL → trait on the anchor genome: 4,346,834 rsID nodes, 4,520,517 variant→gene edges (PTV 110,472, PAV 738,726) with SO class and EVA study from the VCF `VC`/`SID` INFO fields.
3. Sample → accession → population → publication, and sample → gene (predicted LoF): 8,325 samples, ≈6,600 accessions, 11 populations, 3,120,315 LoF pair edges (pop 9 excluded, see below).
4. Publications as nodes with titles: ≈22,168 distinct PMID/DOI ids across the 9 anchors (34,460 gene mentions), 59 IDF PubMed ids (71 DOIs), 6 PMIDs in Ensembl variation source names, 5 population DOIs.
5. Experiment → sample group → PO/EFO/… term → contrast, with citation (369 experiments, 6,604 assays, ≈1,076 contrasts, 27,024 term refs).
6. Gene → organ (`expressed_in`, level/TPM/n_samples) hung off an `Analysis` node for `expression_attributes` (1,033,358 positive + 941,697 negated edges).
7. Provenance on every edge, and `Release`/`Dataset`/`Distribution`/`IngestRun` records that sorghum11 lacks entirely (no `loads` collection; stamps only in `build/.state/*.done`).

### Materialisation rule
Gene nodes for all 128 genomes (5,407,132, so any id resolves). Per-gene annotation edges for the 9 `is_anchor` genomes (288,734 genes; `EXPECT_ANCHORS=9` at `build/config.sh:148`). N:1 relations (gene→genome, gene→tree, gene→taxon, assay→experiment, sample→accession, sample→population) are **node slots**, emitted as edges in KGX only.

## 2. Schema — `schema/gramene_kg.yaml` (LinkML plant profile of Biolink)

`id: https://w3id.org/gramene/kg`, `imports: [linkml:types, biolink:biolink-model]` (pinned 4.4.6 URL), `default_prefix: gramene`. Generated into `schema/generated/`: `json-schema/` (ajv validation in API + build sample validation), `typescript/` (API/UI types), `jsonld/context.jsonld`, `docs/`, `schema-slices.json` (MCP). Python venv `/usr/local/gramene/gramene-kg/.venv` (python3.12, pip 23.2.1 verified) holds `linkml`, `duckdb` (fallback engine), `kgx`.

**Prefixes** (`config/prefixes.yaml` drives the kg30 regex gate, not Bioregistry): Bioregistry forms `insdc.gca` (`^GCA_[0-9]{9}(\.[0-9]+)?$`), `NCBITaxon`, `GO`, `PO`, `TO`, `ECO`, `SO`, `interpro` (`^IPR\d{6}$`), `reactome` (`^R-[A-Z]{3}-\d+…`), `dbsnp` (`^rs\d+$`, resolver override `https://data.gramene.org/pansite-ensembl-115/variation/sorghum_bicolor/$1?content-type=application/json`), `PMID`, `doi`, `gxa.expt` (`^[AEP]-\w{4}-\d+$`), `bioproject`, `infores`, `CHEBI`, `PATO`, `UO`. Local prefixes with resolver `https://data.sorghumbase.org/kg/ui/node/<prefix>:$1`: `gramene.gene` (pattern `^[A-Za-z0-9][A-Za-z0-9._:-]*$`; Bioregistry currently registers `gramene.gene` with the legacy `^GR:\d+$`, so an update request is filed at M0 — Gramene owns the prefix), `gramene.genome`, `gramene.taxon`, `gramene.genetree`, `gramene.qtl` (request widening from `^\w+$` to `^[A-Za-z0-9._-]+$`), `gramene.germplasm`, `gramene.sample`, `gramene.population`, `gramene.varstudy`, `gramene.expt`, `gramene.assay`, `gramene.contrast`, `gramene.tffamily`, `gramene.collection`, `gramene.term` (stub ontology classes), `gramene.analysis`, `gramene.run`, `gramene.release`, `gramene.dataset`, `gramene.dist`, `gramene.software`, `gramene.agent`, `gramene.assoc`. ### Reification rule
Plain edge when metadata is 1:1 with one source (all ETL edges in increment 1, including QTL overlap and LoF pairs). Promote to `Association` node when curators attach a second evidence line, when a relation needs its own citation/retraction history, or arity exceeds subject/object + qualifiers.

### Identity resolution (`build/sql/identity.sql`, also used by `/resolve` and kg20 curated attach)
Gene: exact `_id` → `alt_id` → `synonyms`; **all matches returned with genome**; `Sobic.007G158500` is both the `_id` of a `sorghum_bicolort2tcas` gene (taxon 4558004, 36,924 genes) and an alt_id of `SORBI_3007G158500`, so a bare alias hit is `ambiguous` unless `genome=` is given (default anchor `GCA_000003195.3` for `/resolve?category=Gene`). `normaliseId` (`gramene-g2p/apps/workers/src/stages/validate.ts:328-330`) is applied **only** to germplasm/sample/population strings. Genome: GCA → system_name → registry row. Taxon: rank rule above. Tree: verbatim, never equated across compara dbs except via `leafset_sha1`. Terms/domains/pathways: zero-pad; GO alt_ids via `ontology.go.alt_ids` (12 of 13 missing sorghum ids resolve, e.g. GO:0005887→GO:0005886); obsolete kept. QTL: verbatim. Accession/Sample/Population: tables above. Variant: rsID. Publication: PMID digits / DOI lower. Experiment/Assay/Contrast: accession keys. Collection: hash.

## risks

- RAM pressure (MemAvailable 102 GB, swap 52/63 GB used, WiredTiger 55 of 68.7 GB cap): mitigated by streaming everything, DuckDB memory_limit 16 GB with temp on /scratch, kg00 admission gates (MemAvailable > 50 GB, free swap > 8 GB, `make running` quiet in every build tree), off-peak kg60/kg70, lean edge docs and only two edge indexes.
- Cold-query latency on 7.2k RAID-6 HDD: the KG's indexes must evict live release pages; mitigated by measuring warm and cold at M1a and publishing honest SLOs (p95 < 1 s cold, < 300 ms warm), and by the small working set (two compound indexes).
- Mongo load slower than estimated (maxIndexBuildMemoryUsageMegabytes 200, HDD external sorts): mitigated by a 10% dry load at M1a to calibrate, one createIndexes call per collection, and build-id dbs so a slow load never affects the served build.
- Edge composition larger than planned (QTL 3.6M, variants 4.5M, LoF 3.1M were all underestimated by earlier drafts): mitigated by expectations.json written from measured M1 counts with +-10% gates and a per-QTL cap of 10,000 edges.
- Public exposure depends on people outside the team (gorgonzola proxy, CSHL firewall): request filed at M0; everything is usable on localhost/VPN meanwhile and documented like 70_services.sh.
- Curated layer is the only non-reproducible asset on a host with no backups and an unauthenticated mongod on 0.0.0.0: nightly mongodump cron with 30-day retention and weekly off-volume copy, content_sha256 on every revision, kg00 refusal to target kg_meta/kg_curation, API write client hard-coded to kg_curation.
- Identity churn across releases (gene-tree ids, synthetic taxon ids, genome ids without GCA, vitis/populus assembly changes): never used as foreign keys outside a release, leafset_sha1 and genome_registry.tsv for same_as, curator warnings on tree-targeted assertions, attach reports every build.
- Upstream fetch failures (NCBI, Crossref, EBI FTP, dev.gramene.org curated feeds): snapshots sha256-stamped, cache-first, build continues with `unenriched` flags; curated feed outage fails loudly instead of the silent-empty behaviour of curated.js:17.
- DuckDB Node binding on EL8 (glibc 2.28) may not have prebuilt binaries: fallback to the `duckdb` 1.4.4 legacy binding or the venv Python module, decided in the M0 spike.
- Solr atomic-update erasure of unstored fields: every kept field stored, copyField targets stored=false, and the 62_attr_atomic preflight check run against the kg core at kg70.
- /solr is the tightest data mount (183 GB free, genes70 at 104 GB): kg cores are ~1-2 GB and retention is two builds; kg00 disk gates on /solr, /mongodb and /scratch.
- Pop-9 and species inference errors in germplasm/populations are curation questions, not code: species_confidence and match_method are exposed on the nodes and in the dangling report so curators can correct through the curated layer.
- Mixed ontology versions (node sets from ontology.* 2026-07/110.0, edges from release-tree 2026-06/109.0): made explicit via separate Dataset nodes and knowledge_source_version on edges; alt_id resolution and obsolete/stub nodes keep the dangling gate at zero.
- Bus factor (one engineer): one repo, one `make build`, one `make promote`, one eval command, pm2 only, no new daemon until Neo4j is justified by M4 measurements.
